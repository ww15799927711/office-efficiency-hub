# 场景分流与执行细则 (Dispatch)

本文件是调度中心的"路由表 + 工作流库"。SKILL.md 负责识别与分流，本文件负责每个场景具体怎么干。典型场景完整输入/输出示例见 `references/examples.md`，快速能力边界清单见 `references/capability-list.md`。

**全局约束**：本文件所有 §1~§18 工作流（与 `capability-list.md` 的 **18 个能力场景**一一对应）默认强制遵循 `references/fact_discipline.md`（事实纪律与可信度规范）——所有产出须标注置信度与来源、禁止臆造、不确定明说、被纠正立即改。

**异常处理统一模板**（所有场景通用，避免"模棱两可"）：
- **如果外部依赖缺失**（未装技能 / 未授权连接器）→ 明确说出缺失项 → 给出 1 个内置降级方案（纯文本/本地文件/导出处理） → 给出 1 个可选增强路径（安装/授权什么）。
- **如果输入格式不对 / 文件损坏 / 无法解析** → 明确告知问题 → 给出 2-3 个修正选项（换格式、粘贴文字、分块上传）。
- **如果输出不满足需求** → 先问"具体哪部分不满意" → 给 3 个常见调整方向（更详细/更简短/换个视角/聚焦某个子项）。
- **禁止话术**："可能吧""试试看""你自己处理一下"等模糊表达一律替换为可执行的下一步。

## §1 会议纪要 / 待办提取（通用来源）

适用：用户提供录音转写稿、聊天记录、文档、零散文字，需整理成可执行的会议纪要。腾讯会议来源请改用 meeting-recap-tmeet。

步骤：
1. 通读输入，识别五类信息：决策、行动项（TODO）、风险、争议、开放问题。
2. 产出结构：
   - 会议概览：时间 / 参与人 / 主题
   - 关键决策：结论 + 依据
   - 行动项清单：每项含「负责人 + 截止日 + 验收标准」
   - 待讨论 / 风险：未决事项与潜在问题
3. 行动项强制「动词 + 对象 + 交付物 + 时间」格式，杜绝"跟进一下"等模糊表达。
4. 交付后询问：是否把行动项沉淀进知识库或待办系统。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴文字、录音稿、聊天记录即可独立完成。

**常见异常处理**：
- 输入是音频文件而非文字稿 → 转 §16 音频转写；无转写依赖时按 §16 给出 4 档降级引导。
- 内容过于零散/无会议主题 → 先问"这是什么会议？参会人有哪些？"再整理，不盲猜。
- 行动项不够具体 → 主动提示"是否需要按'动词+对象+交付物+时间'再细化？"
- 多人发言混在一起 → 标注"发言者未区分"，并给出分段建议。

## §2 文档总结 / 长文提炼

步骤：
1. 先明确总结粒度：一句话摘要 / 要点列表 / 分层大纲 / 思维导图。
2. 保留原文关键数据、人名、数字、结论，严禁臆造或改写事实。
3. 视用户意图，输出可附「决策建议」或「行动清单」。
4. 长文优先用 Read/Grep 分段读取，避免单次截断丢失上下文。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴文字、PDF/Word 文字内容即可独立完成。

**常见异常处理**：
- 文件是图片/扫描 PDF 无法直接读 → 先经 §13 OCR 提取文字，再进入总结。
- 用户没说总结粒度 → 给出 4 个选项：一句话摘要 / 要点列表 / 分层大纲 / 思维导图。
- 原文太长超出上下文 → 自动分块读取 + 分段总结，最后合并，不丢关键数据。
- 用户不满意总结深度 → 问"要更详细、更简短，还是聚焦某个章节？"

## §3 邮件 / 消息草拟

步骤：
1. 先与用户确认四要素：收件人角色、目的、语气（正式/随意/委婉拒绝）、是否需附数据。
2. 用 `assets/email-draft-template.md` 结构：主题行 → 开场 → 核心诉求 → 行动召唤 → 落款。
3. 中文商务邮件主题须点明事由；拒绝类先肯定再转折，给台阶。
4. 草拟后附「发送前检查清单」：收件人、附件、时限、语气是否合适。

**零依赖路径**：本场景无需外部 skill/连接器，直接说明收件人、目的、语气即可生成邮件草稿。

**常见异常处理**：
- 用户没说收件人和目的 → 先确认四要素（收件人角色、目的、语气、是否附数据），不盲写。
- 语气不合适 → 提供 3 个版本：正式 / 商务友好 / 委婉拒绝，让用户选。
- 需要引用附件/数据但用户没给 → 明确标注"【附件待补充】"，并列出需要材料。
- 邮件太长发不出去 → 提供精简版（≤150 字）和完整版两版。

## §4 晨间作战简报

适用：每日开工前，把当天会议、待办、重点事项汇成一页纸，对抗碎片化与"无限工作日"。吸收自 SkillHub 日程助手"战略静默"理念，在简报中主动保护用户专注时段。

步骤：
1. 若用户提供了日历/待办/纪要，从中提取「今日会议、待交付、高风险项」。**若未提供，自动从当前会话已生成的会议纪要、行动项追踪表、客户跟进卡片、周报等产物中收集进度，作为简报素材**。
2. 用 `assets/morning-brief-template.md`：今日一览 → 会议（时间/主题/准备）→ 三大重点 → 可委托/可推迟。
3. **战略静默（休息关怀）**：
   - 识别高密度会议时段（如连续 ≥2 小时会议、上午/下午核心时段被切碎），标注红色。
   - 建议至少留出 **1 个 ≥90 分钟的无会议专注块**用于深度工作；无法留出时，建议推迟/取消非关键会议或委托。
   - 连续工作预计超过 4 小时未安排休息，给出"劳逸结合"提示（不强制打断，仅提醒）。
4. 若无输入，基于当前对话上下文生成，并说明假设。

**零依赖路径**：本场景无需外部 skill/连接器，直接说明今日待办/会议即可生成简报。

**常见异常处理**：
- 用户没给日历/待办/纪要 → 从当前会话历史产物中收集；会话为空时说明"基于你提供的文字生成，建议后续授权连接器自动同步"。
- 无高密度会议也提示战略静默 → 仅在有连续 ≥2 小时会议或工作超 4 小时时才触发提醒，避免过度关怀。
- 简报太长 → 默认一页纸；需要详细版时主动询问。

## §5 知识库沉淀

目的：把零散产物变成可检索、可复用的资产，打通信息孤岛。

步骤：
1. 交付任一产物后，主动询问是否沉淀。
2. 用户同意沉淀后，**导出为独立 Markdown 知识库文件**到其指定目录（如 `知识库/分类/标题.md`），结构：标题 + 摘要 + 标签 + 来源 + 日期 + 正文，而非仅口头询问不落地。
3. 去重：写入前先检索是否已有相近条目；存在则更新/追加，不新建重复；旧版标注归档。
4. 若用户使用企业知识库平台（如腾讯乐享 lexiang、ima 知识库），按其连接器/API 写入，不擅自改变结构。
5. **脱敏前置**：沉淀到可外发/共享知识库前，按 `references/privacy_desensitization.md` 先询问是否脱敏（内部私有库可保留原文）。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴零散资料即可整理成 Markdown 知识库文件。

**常见异常处理**：
- 用户没指定目录 → 问"沉淀到哪个目录？"；不指定则默认 `./知识库/分类/标题.md` 并征求同意。
- 资料重复 → 先检索当前知识库，存在则更新/追加，旧版标注归档，不新建重复。
- 含敏感信息 → 按 `references/privacy_desensitization.md` 先问脱敏方式，不默认遮盖。

## §6 文档 / 纪要转 PPT（通用）

适用：把任意素材快速转化为汇报 PPT。覆盖两类输入——
- **A 类（会议纪要类）**：会议已结束，从纪要/录音稿/素材转汇报 PPT（原核心场景）。
- **B 类（通用文档类）**：用户给了一份 Word/文档/方案/报告/长文，想"一键生成 PPT"用于汇报/路演/培训——吸收自 WPS 全家桶"Word→PPT 一键生成"亮点。

步骤：
1. 判定输入类型（A 类 or B 类），确认受众与目标（汇报决策 / 同步进度 / 推动行动 / 培训）。
2. 内容抽取：
   - A 类：从输入提取「背景、关键进展、决策、风险、下一步」五大块。
   - B 类：先经 §2 文档总结理清层级，再抽取「标题层级 → 核心论点 → 关键数据/案例 → 结论」，保留原文数字与人名，不臆造。
3. 用 `assets/pptx-outline-template.md` 生成 PPT 大纲：封面 → 目录 → 内容页 → 结尾。B 类可按文档原标题层级映射成章节。
4. 每页只保留一个核心观点，附 2-4 个支撑要点；B 类长文档可合并次级标题、提炼而非照搬。
5. 调用 `pptx` 技能生成实际幻灯片；用户无明确要求时，默认走简洁商务风格。
6. 交付后询问：是否需要演讲者备注或附录。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴文字/纪要即可生成 PPT Markdown 大纲。

**常见异常处理**：
- 用户没装 `pptx` 技能 → 先产出 Markdown/PDF 大纲，并告知"如需 .pptx 文件，可装 pptx 技能一键生成"。
- 输入是图片/扫描 PDF → 先经 §13 OCR 提取文字，再走 §2 总结，最后转 PPT。
- 内容太满一页塞不下 → 按"每页一个核心观点 + 2-4 个支撑要点"拆分，给出调整建议。

## §7 客户/项目跟进

适用：销售、PM、客户成功等角色，需要把聊天记录、邮件、纪要汇成客户状态。

步骤：
1. 识别客户/项目名，提取关键信息：行业、阶段、负责人、预算/周期。
2. 梳理「上次沟通时间/形式/结论 → 当前阶段 → 待办/风险 → 下次行动」。
3. 用 `assets/customer-followup-template.md` 输出客户跟进卡片。
4. 健康度用绿/黄/红三档，给出依据。
5. 若有多个客户/项目，生成汇总列表。
6. 交付后询问：是否沉淀到 CRM 或客户档案。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴聊天记录/邮件/文字即可生成客户状态卡。

**常见异常处理**：
- 客户/项目名不明确 → 先问"客户/项目名是什么？当前阶段是？"
- 缺少关键信息（预算/周期/负责人） → 在卡片中标注"【待补充】"并列出需要补充项。
- 多个客户混在一起 → 先拆分再分别生成卡片，或出汇总列表让用户确认。

## §8 培训/学习笔记整理

适用：内部分享、外部培训、课程学习后，需要把讲义/字幕/文章整理成可复用笔记。

步骤：
1. 明确来源类型（课程、讲座、文章、视频字幕）和学习目标。
2. 提取核心概念、关键论点、数据/案例、与自己工作的关联。
3. 用 `assets/learning-notes-template.md` 输出：核心概念 → 关键要点 → 关联 → 行动项 → 后续追问。
4. 把抽象概念用自己的话重新表述，避免直接复制。
5. 生成知识卡片：一句话定义 + 适用场景 + 常见误区。
6. 交付后询问：是否沉淀到知识库。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴讲义/字幕/文字即可整理笔记。

**常见异常处理**：
- 来源是视频 → 不自动下载；请用户先导出字幕或粘贴文字。
- 内容杂乱 → 先确认学习目标（考试/实操/分享），再按目标组织。
- 概念过多 → 生成"一句话定义 + 适用场景 + 常见误区"知识卡片。

## §9 行动项追踪

适用：多个会议纪要或零散待办混在一起，需要统一跟踪。吸收自 SkillHub 日程助手"时间冲突"理念，增加截止日期与会议冲突检测。

步骤：
1. 从输入中提取所有行动项，识别负责人、截止日、验收标准。
2. 去重：合并重复或相似事项，标注来源。
3. **时间冲突检测**：
   - 多个行动项落在**同一天截止**（尤其同一负责人）时，用 🚨 标注"截止日期堆叠"。
   - 行动项截止日与已知会议/出差/假期冲突时，标注"日程冲突"并建议调整。
   - 高优先级行动项被低优先级会议占用时间，建议"委托/推迟/缩短会议"。
4. 用 `assets/action-tracker-template.md` 输出统一跟踪表，并在表首或单独"冲突视图"中列出上述风险。
5. 建议调用 `xlsx` 技能生成可编辑表格，方便后续更新状态。
6. 标注阻塞项和高风险项，提醒优先推进。
7. 交付后询问：是否按周/日自动提醒。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴多份纪要/聊天记录即可输出追踪表。

**常见异常处理**：
- 行动项缺少负责人/截止日 → 标注"【待确认】"，并主动列出需要用户确认的事项。
- 多个任务同一天截止 → 标注 🚨"截止日期堆叠"，建议委托/推迟/拆分。
- 表格输出需求 → 如已装 `xlsx` 则生成可编辑表，否则先给 Markdown 表并告知可导出 Excel。

## §10 财务 / ERP（金蝶·用友等）

适用：财务、会计、业务员处理金蝶（K3/云星空）、用友（U8/NC）等 ERP 导出数据后的清洗、对账、报表、凭证整理。

**能力边界（务必讲清）**：金蝶/用友为商业闭源软件，无公开 API，本技能**不直接登录或操作 ERP 系统**；只处理 ERP 导出的 Excel/CSV，做"数据搬运 + 核对 + 报表"这一层——这正是财务每月最机械、最易错的部分。

步骤：
1. 明确任务类型：数据清洗 / 凭证整理 / 对账 / 财务报表，四种之一或组合。
2. 数据清洗（针对导出明细）：
   - 去冗余表头/合计行/分页符；统一科目编码；金额文本转数值；日期格式统一（YYYY-MM-DD）。
   - 输出标准化明细表，建议调用 `xlsx` 技能便于后续透视。
3. 凭证整理：
   - 用 `assets/finance-erp-template.md` 的凭证结构：日期｜凭证字号｜摘要｜科目编码｜科目名称｜借方｜贷方｜附件。
   - 校验借贷平衡，科目编码对齐 ERP 科目表。
4. 对账：
   - 银行对账：银行流水 vs 银行存款日记账；往来对账：应收/应付明细 vs 客户/供应商对账单。
   - 输出差异清单（金额、方向、可能原因），标注未达账项。
5. 财务报表：
   - 三大表：资产负债表、利润表、现金流量表；说明取数口径与期间。
   - 校验勾稽关系：资产 = 负债 + 所有者权益；利润表净利润 = 所有者权益变动中净利润。
6. 交付检查清单（强制）：借贷平衡、科目与 ERP 一致、报表勾稽通过、数据口径已注明。
7. 交付后询问：是否沉淀为财务模板/知识库复用。
8. **敏感字段（脱敏前置）**：产出含银行账号/税号/个人身份证时，按 `references/privacy_desensitization.md` **先询问**脱敏方式——对内入账/对账可保留原文，对外/共享再脱敏，不默认遮盖。

**零依赖路径**：本场景无需外部 skill/连接器，直接上传 ERP 导出的 Excel/CSV 即可清洗、对账、出凭证草稿。

**常见异常处理**：
- 用户要求直连金蝶/用友入账 → 明确拒绝："本技能不直连 ERP 数据库/不入账，请使用我生成的凭证草稿在 ERP 中人工执行。"
- 导出文件格式混乱（多表头、合计行、分页符） → 先清洗再计算，并说明清洗规则。
- 借贷不平衡 → 列出差异项，标注"需人工复核"，不强行配平。
- 含敏感字段 → 按 `references/privacy_desensitization.md` 先问脱敏方式。

3. **若未授权**：提示用户先到连接器管理页启用对应连接器；在用户确认前，降级为"导出文件 → 按 §1–§9 处理"，**不伪造接口或冒充已接入**。

**零依赖路径**：本场景无需外部 skill/连接器，直接上传协作平台的导出文件即可处理。

- 连接器调用失败 → 自动重试 3 次（1s→3s→5s），仍失败则降级导出处理，不伪造接口。

## §12 数据分析与透视（自然语言驱动，对应 WPS 表格高级分析能力）

适用：用户有原始数据（销售明细、运营日志、调查结果、ERP 导出、问卷等），需要透视、分组聚合、统计指标、可视化图表或数据看板。支持**用户用自然语言直接说需求**（"帮我分析下这季度销售""哪些产品最赚钱""按月看趋势"），由 skill 自动识别意图并匹配分析动作——吸收自 WPS 全家桶"自然语言数据分析"亮点，对应 WPS 表格的"数据透视 + 统计分析 + 图表"强项。

步骤：
0. **意图识别（自然语言驱动）**：解析用户口语化诉求，映射到分析类型——
   - "看看整体/概览/多少" → 描述性统计（总量/均值/占比）
   - "按 XX 分/对比/哪个最多" → 分组对比（透视 + Top N）
   - "趋势/变化/逐月/同比环比" → 时间序列趋势
   - "构成/占比/分布" → 结构占比（饼环/帕累托）
   - "关系/是否相关/异常" → 相关性/异常检测
   用户已显式声明目标时，跳过识别直接执行。
1. **定方向**：明确分析目标（上述五类之一或组合），并确认可选维度与期间。
2. **数据体检**（必做，先于一切计算）：缺失值、重复行、类型校验（金额数值化、日期归一 YYYY-MM-DD）、单位统一、口径说明（来源/期间/是否含退单）。
3. **透视与聚合**：
   - 透视表四要素：行字段 / 列字段 / 值字段（求和·均值·计数·最值）/ 筛选字段。
   - 分组聚合：按维度 GROUP BY + 聚合函数，输出分组明细 + 小计。
   - 时间维度：按日/周/月/季滚动，同比（YoY）、环比（MoM）。
4. **统计指标**：总量、占比、均值、中位数（抗极值）、标准差、Top N、帕累托（二八定位）。详细字段见 `assets/data-analysis-template.md`。
5. **可视化**：柱状（对比）/ 折线（趋势）/ 饼环（占比）/ 热力（交叉强度）/ 散点（相关性）；调用 `xlsx` 生成图表。财务/股市场景遵循**红涨绿跌**，其他默认中性配色。每张图含标题、坐标轴单位、期间、口径脚注。
5-B. **交互看板（可选增强）**：当需一屏看全 / 投屏 / 钻取，或产出要进周报·晨报·PPT 且含多图时，在 xlsx 静态图之外**可选**生成自包含 ECharts HTML 看板或 SVG 信息图（详见 `assets/data-analysis-template.md` 五-B）。用户无浏览器/拒绝 HTML 时回退纯 xlsx + Markdown 表，不卡死。

6. **结论与建议**：用数据支撑 2-3 条业务结论，附"数据口径与局限"说明，禁止臆造数字。
7. **交付**：建议 `xlsx` 输出「原始表 + 透视表 + 图表」三 sheet 可编辑文件；汇报场景转 `pptx` 单页图表。交付前按 `assets/data-analysis-template.md` 检查清单逐项核对。

**零依赖路径**：本场景无需外部 skill/连接器，直接上传 Excel/CSV 即可做透视、统计、可视化分析。

**常见异常处理**：
- 用户只说"分析下销售"但没说目标 → 先做意图识别，给出 5 类分析选项让用户选或默认做描述性统计 + Top N。
- 数据有缺失/重复 → 先做数据体检，列出问题，再让用户决定是否继续/清洗。
- 没装 `xlsx` 技能 → 输出 Markdown 表格 + 文字结论 + ECharts HTML/SVG 看板（可选），告知"如需 .xlsx 文件可装 xlsx 技能"。
- 文件太大 → 按文件大小限制分块处理或建议抽样。

## §13 PDF / 图片文字提取（OCR 预处理）

适用：用户给了图片、扫描 PDF、截图、拍照文件，需要把里面的文字提取出来，作为后续办公处理的输入。

**能力边界**：本 skill 只做调度与后续加工，**不重复实现 OCR**。OCR 本身可选调用用户已安装的 `pdf-image-text-extractor` 类 OCR 专用技能；若未安装，走内置 `pdf` 工作流；再不济则引导用户先自行提取文字后再粘贴给本 skill。

步骤：
1. 确认输入类型：图片 / 单页 PDF / 多页 PDF / 是否手写 / 是否含表格。
2. 调用已安装的 `pdf-image-text-extractor` 类 OCR 技能提取文字：
   - 要求输出 Markdown 结构化文本，保留段落、列表、表格层级。
   - 若原图是表格，同时输出 Markdown 表格和 CSV 文本，便于后续进 `xlsx` 做透视。
3. 质量标注：
   - 标注识别置信度低、模糊、乱码、缺字、表格错位的区域。
   - 对不确定的字词加 `[?]` 标记，不擅自猜测。
4. 下游分流（提取后立即建议，不默认执行）：
   - 会议内容 → §1 纪要提取
   - 长文档/文章 → §2 文档总结
   - 客户沟通记录 → §7 客户/项目跟进
   - 培训讲义 → §8 培训/学习笔记
   - 待办清单 → §9 行动项追踪
   - 发票/凭证/对账单 → §10 财务/ERP
   - 数据截图 → §12 数据分析与透视
   - 通用资料 → §5 知识库沉淀
5. 交付检查（见 `assets/ocr-prep-template.md`）：文件/页数、结构保留、异常标注、表格双格式、下游建议。

**零依赖路径**：本场景无需外部 skill/连接器，直接上传图片/PDF 即可走内置 OCR 预处理（调用 `pdf` 技能）或提示用户粘贴文字。

**常见异常处理**：
- 没装 `pdf-image-text-extractor` → 调用 `pdf` 技能；`pdf` 也不可用时，提示用户粘贴文字。
- 识别置信度低 → 对不确定字词加 `[?]`，不擅自猜测。
- 复杂排版表格错位 → 输出 Markdown 表格同时说明"复杂表格建议人工核对"。
- 手写体/潦草 → 明确说明"手写识别率低，建议重新扫描或人工录入关键字段"。

## §14 合同审查（采购 / 法务 / 财务视角）

适用：采购、法务、财务、业务人员审查各类合同（买卖/采购/服务/劳动/合作/知识产权/租赁等），识别风险点、缺失条款、版本差异。

**能力边界**：本 skill **不替代律师或专业法务**，审查结果仅为 AI 辅助参考。重大合同或复杂法律关系应交执业律师/企业法务最终复核。

**敏感字段（脱敏前置）**：审查产出含主体身份证号/统一社会信用代码时，按 `references/privacy_desensitization.md` **先询问**脱敏方式——内部使用可保留原文，对外分享再脱敏，不默认遮盖。

步骤：
1. 获取合同文本：用户直接粘贴、上传 Word/PDF/图片，或先经 §13 OCR 提取文字。
2. 判定合同类型：商事/服务/劳动/合作/知识产权/其他。
3. 可选调用用户已安装的 `audit-new` 类合同审查专用技能进行专业审查；若未安装，走本文件内置工作流。
4. 内置审查维度（三视角）：
   - **通用结构**：主体信息、标的、金额、付款、交付、违约责任、争议解决、生效/终止。
   - **采购视角**：供应商资质与授权、交付/验收、质保、付款条件、违约罚则、保密与知识产权归属。
   - **法务视角**：合法性、权利义务对等、免责条款合理性、知识产权/保密/竞业、争议管辖/法律适用。
   - **财务视角**：价格与税率、付款节点、发票类型与时点、预算与成本归属、保证金/押金/预付款、退款与赔偿财务影响。
5. 输出：
   - 合同摘要（类型、主体、标的、金额、期限、关键义务）
   - 风险清单（位置 | 描述 | 高/中/低 | 建议修改）
   - 缺失条款提示与补充建议
   - 版本对比（若提供多版）：变更项、影响、需复核点
   - 总体风险评级 + 签署建议
   - **免责声明**：本结果由 AI 辅助生成，不构成正式法律意见。
6. 下游衔接：重大风险进周报/报告（周报模板见 assets/weekly-report-template.md），修改/跟进事项进入 §9 行动项追踪，常用合同条款沉淀进 §5 知识库。

**零依赖路径**：本场景无需外部 skill/连接器，直接粘贴合同文字/上传 Word/PDF 即可走内置三视角审查。

**常见异常处理**：
- 没装 `audit-new` 专业审查 skill → 走内置工作流，并说明"如需更专业的审查可装 audit-new skill"。
- 合同类型不明确 → 先问"这是买卖/服务/劳动/合作/知识产权/租赁中的哪类？"
- 用户要求正式法律意见 → 明确拒绝并建议"请咨询执业律师/企业法务，本结果仅为 AI 辅助参考"。
- 合同页数/条款过多 → 分段审查，先出总体摘要再逐条风险。

## §15 发票 OCR 入账（采购/财务/业务）

适用：采购、财务、业务人员拿到纸质发票、发票 PDF、发票截图，需要识别信息 → 结构化 → 核对 → 生成凭证草稿/入账。吸收自 WPS 全家桶"Excel 发票 OCR 入账"亮点，与 §13（OCR 预处理）+ §10（财务 ERP）衔接，是财务端口高频刚需。

**能力边界**：本 skill **不直接操作金蝶/用友等 ERP 入账**；OCR 可选调用已安装的 `pdf-image-text-extractor` 类技能（见 §13），未安装时走内置 `pdf` 工作流。只产出"结构化发票明细 + 凭证草稿 + 异常清单"，最终入账由用户在 ERP 中执行或人工复核。

**敏感字段（脱敏前置）**：发票含购买方/销售方税号、银行信息、申请人身份证时，按 `references/privacy_desensitization.md` **先询问**脱敏方式——内部入账/报销可保留原文，对外/共享再脱敏，不默认遮盖。

步骤：
1. **提取**：经 §13 OCR 把发票图片/PDF 转文字；支持多张发票批量提取。
2. **结构化**：按 `assets/invoice-ocr-template.md` 字段表填值，金额/税额/价税合计数值化，校验 金额+税额≈价税合计（容差 0.01）。
3. **校验**：重号检测（防重复报销）、税号合法性（15/18/20 位、购买方与本单位一致）、税率合理性（与货物类型匹配）、同批多张发票价税合计之和与合同/订单比对。
4. **入账/凭证草稿**：用 §10 凭证结构生成凭证草稿（日期｜凭证字号｜摘要｜科目｜借方｜贷方），常用科目映射见模板。
5. **交付**：输出「发票明细表（进 xlsx）+ 凭证草稿 + 异常清单」；异常项标红待人工复核。
6. **交付检查**（强制，见模板）：字段完整、三栏勾稽、无重号、税率合法、借贷平衡、附免责声明。
7. **下游衔接**：凭证草稿 → §10 财务 ERP；报销待办 → §9；常用科目/供应商 → §5 知识库。

**零依赖路径**：本场景无需外部 skill/连接器，直接上传发票图片/PDF 即可走内置 OCR 识别与凭证草稿生成。

**常见异常处理**：
- OCR 提取失败 → 提示用户手动粘贴发票关键字段（代码/号码/金额/税号）。
- 金额/税额/价税合计不平 → 列出差异，标注"需人工复核"，不强行配平。
- 重复报销 → 标记 🚨"重号风险"，建议核对历史报销记录。
- 用户要求直接入账 → 明确拒绝："本技能不直连 ERP/不入账，请使用凭证草稿在 ERP 中人工执行。"

## §16 会议录音转文字（音频转写 → 纪要）

适用：用户上传会议录音（.mp3/.wav/.m4a）或任意音频，希望"先转成文字，再整理成纪要/行动项"。**本技能不自带 ASR（语音识别）引擎，只做调度与后续加工**，转写能力必须来自外部依赖。

**核心原则**：没有转写能力时，**宁可不干活，也要给出可落地的下一步**——绝不只回"我做不到"，也绝不伪造/猜测转写内容（违反事实纪律）。

**转写依赖四级阶梯（按最省事 → 最完整）**：
1. **腾讯会议 tmeet 连接器**（最省事，开会场景）：若用户用腾讯会议，引导去连接器页"信任"启用 `tmeet`；云录制自带转写，启用后直接拉取转写稿走 §1。
2. **已安装的语音转文字 skill**（长期自动化）：若用户已装任意语音转文字类 skill，优先调用它转写，再走 §1。
3. **本机 ASR 引擎（数据留本地）**：引导用户在本机部署 `faster-whisper`（详见 `assets/audio-asr-guide.md` 的实测安装/调用指引）；用户转写后把文字稿发回，走 §1。
4. **粘贴文字稿（零门槛）**：引导用户用任意现成工具先把音频转成文字，把文字稿发来，本技能直接走 §1 整理纪要。

**无依赖时的标准引导话术**（检测到音频但环境无任何转写能力时输出，模板见 `assets/audio-asr-guide.md`）：
> 检测到音频文件，但当前环境没有可用的转写能力（未启用腾讯会议、未安装语音转文字技能、本机也未配置 ASR）。你可以任选一种方式继续：
> ① 最省事：用任意工具转成文字稿发我，我直接整理纪要；
> ② 开会用腾讯会议 → 去连接器页信任「腾讯会议」即可自动转写；
> ③ 想长期自动化 → 装一个语音转文字 skill，装好告诉我；
> ④ 数据要留本地 → 本机自托管 faster-whisper（我可给安装指引）。
> 选哪个？或直接把转写好的文字粘贴给我也行。

步骤（环境具备转写依赖时）：
1. **转写**：经上述任一依赖把音频转为文字稿；尽量保留说话人分段（若引擎支持）。
2. **语种与格式**：中文音频默认简体输出；若引擎输出繁体（如部分 faster-whisper 默认），按用户习惯转为简体（通常转），可用 OpenCC `t2s` 处理。
3. **纪要整理**：把转写稿作为 §1 的输入，走"纪要/待办提取"工作流，产出结构化纪要 + 行动项。
4. **事实纪律**：转写稿属"待确认/推断"级来源，口语错误、同音字、口音导致的错字须在纪要中标注 `[转写待核对]`；关键数字、人名、条款须提示用户人工核对（见 `references/fact_discipline.md`）。
5. **下游衔接**：行动项 → §9；需生成周报/邮件 → §3；常用术语/与会人 → §5 知识库。

## §17 周报 / 日报 / 周期报告（工作总结）

适用：用户要写周报、日报、月报、复盘、工作总结、方案汇报，需要把分散的进度/纪要/聊天记录汇总成结构化周期报告。吸收自 WPS 全家桶"一键生成周报"亮点，对应 WPS 文字的"报告/总结"强项。

步骤：
0. **定类型与周期**：确认周报/日报/月报/复盘 + 信息来源（多份纪要、聊天记录、项目进度、行动项）。
1. **收集汇总**：从用户素材中自动抽取进度；素材为会议纪要/行动项时，先经 §1 纪要提取 / §9 行动项追踪汇总，再归类到"本期完成 / 进行中 / 风险阻塞 / 下期计划 / 需协调"。
2. **结构化填值**：按 `assets/weekly-report-template.md` 字段填（完成情况用 ✅/🟡/🔴 标注，关键数字附来源）。
3. **续写生成**：产出 Markdown/Word 报告；需要正式 Word 时可选调用 `docx` 技能。
4. **事实纪律**：进度数字、人名、金额标注来源；未确认进展标 `[待确认]`，不臆造"已完成"。
5. **下游衔接**：报告正文可经 §3 转邮件发送；复盘要点沉淀进 §5 知识库；阻塞项进 §9 行动项追踪。

**零依赖路径**：本场景无需外部 skill/连接器，直接基于文字/文件素材按模板生成周期报告。

**常见异常处理**：
- 用户没给素材 → 先问"这周做了哪些？或把纪要/聊天记录发我"，或给空白模板让用户填。
- 信息分散在多个文件 → 逐个读取汇总，标注每条来源。
- 没装 `docx` 技能 → 输出 Markdown，告知"装 docx 可出 Word"。
- 内容含敏感信息 → 按 `references/privacy_desensitization.md` 先询问脱敏方式，不默认遮盖。

## §18 表格 / 数据处理（清洗 · 合并 · 格式化 · 简单计算）

适用：用户有 Excel/CSV 或表格类需求——数据清洗、去重、合并、格式化、列拆分/拼接、简单公式计算、统一表头与对齐。是 §12 数据分析与透视的"前处理"环节，也为 §10 财务 ERP 提供干净数据源。

**能力边界**：本 skill 不处理复杂数据库操作、不做预测建模；复杂透视/统计/可视化见 §12 数据分析与透视。

步骤：
0. **定目标**：确认清洗 / 合并 / 格式化 / 简单计算，并确认关键字段（用于合并的 key）。
1. **读取**：上传 Excel/CSV 或直接粘贴表格；图片表格先经 §13 OCR 提取。
2. **清洗**：去重、去空行、类型校验（金额数值化、日期归一 YYYY-MM-DD）、统一单位与千分位。
3. **合并**：多表按 key 字段横向合并（VLOOKUP 式匹配）或纵向堆叠；列出匹配/未匹配行。
4. **格式化与计算**：统一表头、列宽、对齐；求和、占比、差值等简单公式；拆分/拼接列。
5. **输出**：`xlsx` 可编辑文件（推荐）或 CSV/Markdown 表。
6. **下游衔接**：清洗后数据进 §12 做透视统计；财务数据进 §10 财务 ERP；结果进 §5 知识库复用。

**零依赖路径**：本场景无需外部 skill/连接器，直接上传 Excel/CSV 或粘贴表格即可做清洗/合并/计算。

**常见异常处理**：
- 没装 `xlsx` 技能 → 输出 CSV（纯文本通用）/ Markdown 表，告知"装 xlsx 可出 .xlsx 文件"。
- 合并 key 不匹配 → 列出不匹配行，让用户确认 key 字段或手动对齐。
- 文件过大 → 分块处理或建议抽样。
- 表格是图片/扫描件 → 先经 §13 OCR 提取文字再处理。

## 落地原则

### 一、通用工程原则
- 80/20：先啃最高频、最低价值任务，不追求一次性全自动。
- 先标准化后自动化：理清结构、统一口径再生成。
- 凡有专用技能（meeting-recap-tmeet / pptx / docx / xlsx / pdf / pdf-image-text-extractor / audit-new）一律调技能，不重写。
- 财务场景口径必须对齐用户 ERP 的科目表与会计期间，禁止臆造科目或金额。
- 接入型办公软件可选调 WorkBuddy 内置连接器；已授权时直接拉取，未授权时降级导出处理，不伪造接口。
- 默认简体中文；中国股市相关遵循红涨绿跌。

### 二、Office 引擎与运行稳定性（吸收自 WPS 全家桶亮点）
- **四引擎智能识别（输出层）**：生成/编辑 Office 文件时，按"已安装环境"优先级选择执行引擎——
  1. 用户本机已装 **WPS**：优先用 WPS 兼容格式（.docx/.xlsx/.pptx 原生兼容）；
  2. 已装 **MS Office**：输出 Office Open XML，WPS 与 MS 双向兼容；
  3. 已装 **LibreOffice**：可经 headless 转换/校验；
  4. 以上皆无：**纯 Python 库**（python-docx/openpyxl/python-pptx）兜底生成。
  本 skill 默认走第 4 种（纯 Python，跨平台最稳），仅在用户明确有某引擎需求时切换；输出一律用 WPS/MS 通用的 OOXML，避免兼容问题。
- **自动重试**：调用外部命令/连接器/转换失败时，**自动重试最多 3 次**，每次间隔递增（1s→3s→5s），3 次后仍失败再向用户报错，不静默丢弃。
- **硬件自适应**：处理大文件/大批量时，检测 CPU 核数、可用内存，动态调整超时（默认 60s，大文件 120s+）与并发线程数；内存不足时主动降级为分块处理，不 OOM 崩溃。
- **文件大小限制**：单文件 < 50MB 直接处理；≥ 50MB 建议用户先分片/精简，或说明"将分块读取、分批产出"，不一次性载入。
- **失败可恢复**：长任务中途失败需能断点续跑或从最近检查点恢复，避免重头来过。

详见 `references/best-practices.md`（10 个最佳实践 + 20+ 避坑指南）。

**零依赖路径**：本场景是唯一强依赖场景——音频→文字必须借助外部转写能力；但无依赖时，本 skill 仍给出 4 档可落地方案（粘贴文字稿 / 腾讯会议 tmeet / 语音 skill / 本机 faster-whisper），不卡死、不伪造。

**常见异常处理**：
- 环境无任何转写能力 → 按 `assets/audio-asr-guide.md` 输出 4 档引导话术，让用户选一个执行。
- 转写稿是繁体 → 用 OpenCC `t2s` 转简体（需本机有 opencc-python-reimplemented）。
- 口语错误/同音字/口音 → 在纪要中标注 `[转写待核对]`，关键数字/人名提示人工核对。
- 音频质量差（远场/重叠/窄带） → 说明"当前音频质量会导致准确率下降，建议靠近麦克风录制或使用专业设备"。
